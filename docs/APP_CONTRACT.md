## Inference contract

Module `services.inference.registry`: `ModelRegistry(model_root: Path)`, `status(profile: str) -> dict`, `predict(profile: str, items: list[dict]) -> list[dict]`, `ModelUnavailable` exception. Model root `runtime/models`, mỗi profile ở `neu/` hoặc `uit/`. Lazy load một model; không network ở inference. Status `{available:bool,reason:str|null,model_id:str|null,model_version:str|null,schema_id:str}`. Predict input `{item_id,revision_id,text}`; output từng dòng giữ IDs `{item_id,revision_id,model_id,model_version,schema_id,sentiment:{label_id:int,scores:number[]},topic:{label_id:int,scores:number[]},token_count_before_truncation:int,truncated:bool,warnings:string[],duration_ms:number}`. ModelUnavailable khi thiếu/hỏng/schema mismatch. Worker backend quản lý queue/lease/fencing, gọi registry và inject registry double chỉ trong tests. Không expose env production fixture switch.

### Fix behavior agreed 2026-11-06 (R3–R8)

- Runtime allocation/inference failures do not invalidate artifact readiness. Only proven artifact integrity/schema/structural defects are cached as unavailable; successful prediction clears relevant failure state. API and worker registries are independent.
- An unfinished microbatch atomically commits progress, returns its job/run to `queued` and releases the lease. The next claim increments the fenced attempt, so quick priority cannot expire a suspended bulk lease.
- CSV `selected_run_id` is the export selection. Row `prediction_id`, `run_id`, `model_id`, `model_version` identify an actual prediction for the exported revision and are empty otherwise. `prediction_status=processed|failed|unprocessed`; per-task `review_*_source_prediction_id` keeps human provenance independent. Explicit historical export still pins original run revisions.
- Temporary quick payloads expire 15 minutes after terminal status. A worker deadline runs cleanup every 30 seconds during backlog and keepalive during inference, normally within 35 seconds after TTL (SQLite lock contention can delay maintenance). Queued/active quick jobs and explicitly saved durable copies are protected.
- Manual Tab upload sends the single TAB character, consistent with auto-detection and the backend delimiter validator.
- OOF recovery replays all 30 teachers in archived source order and exactly reproduces float64 softmax averaging → float32 assembly → float16/float32 stored targets. The audit records stored dtypes and float32 training conversion, preserving all original coverage/hash/provenance checks.

## Ownership

### Fix contract agreed 2026-11-06 (R1/R2)

Review PUT accepts optional `source_prediction_id: string | null`. A non-null explicit source must identify a prediction for the same item, current input revision and schema; `confirmed` additionally requires the requested task label to match that prediction. It may belong to a different run than the displayed `run_id`. Omission retains the existing selected-run prediction behavior. Null defaults to the selected prediction for `confirmed`, and clears the source for `corrected`/`unreviewed`; the API preserves omission with `exclude_unset=True`. Invalid or mismatching sources return 409 `CONFIRM_REQUIRES_PREDICTION`; input and review revision checks remain mandatory. No database schema change is needed.

The UI draft stores its saved label/source and its own `base_review_revision` per task. Note-only saves preserve that label/source; an explicit reconfirm action selects the displayed prediction. Refetch or 409 must not advance a dirty draft's base. Conflict resolution shows the server review and offers loading it or explicitly rebasing the retained draft after comparison. Successful saves and deliberate resolution may advance the draft base.
