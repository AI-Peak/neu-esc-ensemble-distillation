# Local API and persistence

Run from the repository root with the installed API dependencies:

```powershell
python -m uvicorn services.api.main:app --host 127.0.0.1 --port 8765 --no-access-log
python -m services.worker --runtime-dir F:\DPL_NEU-ESC\runtime
```

`FEEDBACK_RUNTIME` overrides the default `runtime` directory for both processes. The worker also accepts `--runtime-dir` and `--once`. Production uses `services.inference.registry.ModelRegistry` and never fabricates predictions. A missing or invalid artifact produces `409 MODEL_UNAVAILABLE` when a run is requested. OpenAPI is available at `/docs`. The API serves `apps/web/dist` from the same origin after frontend build.

The durable database is `runtime/workspace.sqlite3`. SQLite WAL, foreign keys, busy timeout and versioned migrations are enabled independently by API and worker startup. Migration application is serialized with `BEGIN IMMEDIATE`. Application snapshots, immutable CSV bytes, import previews and all audit records live in this database. There are no separately mutable export files. Deleting a dataset cascades through its owned records and snapshots, including active jobs, revoking outstanding leases.

Run snapshots pin item revision IDs, schema, model ID and model version. A selected `run_id` shows the original text, with `stale=true` after an edit. With no `run_id`, queries show current text and use only the latest dataset run, accepting its predictions only where the input revision still matches. They never fill gaps with predictions from earlier runs. References are explicit and never become operational fallback labels.

Review revisions are append-only, independent for sentiment and topic, and attached to an input revision/schema. Expected input and review revisions prevent lost updates. Confirmation requires an existing matching AI label; correction works without a model. Optional `run_id` selects the displayed AI prediction. Optional `source_prediction_id` preserves a saved review's source across displayed runs: an explicit non-null source must belong to the same item, current revision and schema; confirmation additionally requires the requested task label to match that source. Invalid sources return `409 CONFIRM_REQUIRES_PREDICTION`. Omitted/null source on confirmation uses the selected displayed prediction. For corrected/unreviewed reviews an explicit null clears the source, while an omitted source retains the existing displayed-prediction default. This lets note-only saves preserve label/source, with deliberate reconfirmation choosing another prediction. Reviews against stale input are rejected. Restore creates a new review revision from a compatible historical record. Editing text starts a fresh input revision without copied labels or reviews.

Items, summaries and exports use the same filter implementation. Summary denominators count only the filtered rows carrying the relevant labels. The `needs_review` rule is an operational heuristic: incomplete task review, row error, truncation, or either task's maximum model score below 0.6. It is not calibrated error detection. CSV exports freeze the selected item/review/prediction records and include the separate AI/reference/human fields plus `label_source` and `selected_sentiment`/`selected_topic`. `selected_run_id` identifies the export's selected/latest run, while row `prediction_id`, `run_id`, `model_id` and `model_version` identify only an actual prediction matching that row's revision. These fields are empty for rows without a prediction. `prediction_status` is `processed`, `failed` (a matching run-item error), or `unprocessed` (no matching prediction/error). Editing or appending after a run therefore never assigns its model provenance to unanalyzed text. Explicit historical exports pin the run's original revisions and omit later appends. Per-task `review_*_source_prediction_id` records human provenance separately, including reviews confirmed against another run. Exports have a UTF-8 BOM and prefix dangerous formula strings with an apostrophe, including notes and values preceded by whitespace.

Jobs claim atomically and infer outside the transaction. Claims have a monotonic attempt, owner, lease expiry and heartbeat. Each microbatch commit rechecks the lease/attempt and atomically writes predictions and progress. An unfinished job returns to `queued` and releases ownership/lease in that same transaction; its next claim advances the attempt. This fences the old batch and lets arbitrarily long quick jobs preempt bulk work without expiring a suspended bulk lease. Output IDs, frozen model/schema, probabilities and truncation metadata are validated before any write. A stale worker cannot commit. An expired active lease becomes `interrupted`; retry is explicit and retains the run ID, frozen model/version, and successful rows. Retry only accepts the same model/version. Cancel is checked between microbatches and before commit; cancelling a yielded queued job terminates immediately. An OS file lock permits one production worker per runtime; quick jobs have priority between microbatches. Worker errors persist per row without copying exception messages containing input text.

Quick jobs use `datasets.temporary=1`, never appear in dataset lists, and expire 15 minutes after terminal status. Startup cleanup and a worker maintenance deadline remove expired data independently of queue idleness. Every poll checks the deadline; during long model load/inference the keepalive thread checks it too. The default deadline is 30 seconds with a maximum 5-second maintenance tick, so expiration is normally collected within 35 seconds of TTL, including continuous backlog and blocked inference. SQLite transactions serialize cleanup with claims/retries; database lock contention may add its 30-second busy timeout, after which locked/busy maintenance is retried on the next tick. Cleanup first recovers expired leases, and never removes a temporary dataset with a queued/running job even if an old expiry marker exists. Orphan quick imports also expire. A sentence explicitly added to a durable dataset is a separate durable revision and survives temporary cleanup. Backup must remove temporary datasets, previews and worker heartbeat records from its SQLite snapshot (see the provided backup script). Import preview tokens expire after 15 minutes. CSV accepts strict UTF-8/BOM, chosen delimiters and quoted newlines; commit revalidates the selected column, structural row errors, optional reference maps, and the 500 row / 5 MB / 5,000 character limits.

Tests inject registry doubles through `create_app(runtime_dir, registry, start_worker=False)` and `Worker(runtime_dir, registry)`. Production has no environment switch to enable doubles.

```powershell
python -m pytest tests/api -q
python -m pytest tests/integration/test_worker_boundaries.py -q
```

The backend regression suite covers cross-run confirmation sources and rejection boundaries; edit/append/failed/historical CSV provenance and immutable snapshots; transactional yield with several quick jobs longer than the lease, stale claims and cancel/retry; and scheduled TTL cleanup during blocked inference and continuous backlog with active/durable-data protection. These use isolated temporary runtimes and injected registry doubles, not a production checkpoint or the running app's database.
